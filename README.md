# LUT 批量导出器

给 iPhone 拍的 **Apple Log / Apple Log 2 灰片**批量套 LUT 并导出的 macOS 工具。

原生 Mac 窗口，不需要打开 DaVinci Resolve，不需要剪映，不需要一条条手动加滤镜。拖一个文件夹进来，选 LUT，点开始，去干别的。

---

## 为什么会有这个工具

用 iPhone Pro 系列拍 Log 灰片已经是很常见的做法，但从素材到成片中间横着几个坑：

1. **灰片不能直接套风格 LUT**。网上买的「万能 LUT 包」几乎全是风格型（按场景命名：风光人像、城市街景、晚霞风光），它们是给**已经调好色的 Rec.709 画面**用的。直接套在 Log 灰片上 → 画面发灰、发脏、肤色发橙。这不是 LUT 不好，是顺序少了第一步。
2. **转换 LUT 不好找**。正规的 Apple Log → Rec.709 转换 LUT，要么在 Apple 白皮书配套资源里，要么得自己在 Resolve 里用 Color Space Transform 生成一个。
3. **批量处理麻烦**。Resolve 建时间线一条条渲染，或者写 ffmpeg 命令循环，都不省事。

这个工具把三件事一次解决：**先认清素材是什么曲线 → 用正确的转换曲线还原 → 再叠你的风格**。

## 功能

### 素材识别

- 打开素材目录即逐条判定：Apple Log 2 / Apple Log / 其它 Log / Rec.709 已转换
- 两级判据：先看文件元数据（`AppleLog2`、`arib-std-b67`、`smpte2084`、`bt709` 等标签，命中即高可信）；元数据没有时抽单帧看像素特征（灰片饱和度极低）
- **明确承认能力边界**：Apple Log 1 与 Log 2 的像素特征几乎一样，无法从画面数据区分。所以给了手动下拉，按机型指定
- 一批里混了几种曲线会直接标「素材类型不一致」，提示分开处理

### 两级 LUT

| 槽位 | 作用 | 例子 |
|---|---|---|
| ① 转换 LUT | 把 Log 曲线翻译成 Rec.709 | `AppleLog2_to_Rec709.cube` |
| ② 风格 LUT | 叠在上面的创作风格 | 你的风格包 |

- 强度可调（0–100%，只作用于最后一级，转换 LUT 始终 100%）
- 灰片但 ① 槽空着 → 顶部亮橙条拦截
- LUT 库支持收藏、只看收藏、最近用过、显示来源子文件夹、从列表移除（不删文件）

### 内置还原曲线（不需要任何 `.cube` 文件）

没有转换 LUT 也能出正常色。点「仅色彩还原」，工具用内置曲线把灰片还原成正常画面，不叠加任何风格。

曲线不是凑数的近似货，是按 Apple 白皮书公开的常量**现场用数学算出来的**：

| 项目 | 值 |
|---|---|
| 曲线常量 | `R0=-0.05641088` `Rt=0.01` `c=47.28711236` `β=0.00964052` `γ=0.08550479` `δ=0.69336945` |
| 校验 ① | `encode(0.18) = 0.4882725` —— 白皮书「18% 灰落在 10bit 500」 |
| 校验 ② | `decode(1.0) = 12.00` —— 白皮书「clip at 1200% scene reflection」 |
| 校验 ③ | 编码/解码往返误差 4.4e-16 |

**一个反直觉的事实**：Apple Log 和 Apple Log 2 的 **gamma 曲线完全相同**，区别只在色域——

| 曲线 | 色域 | 原色（CIE xy，D65） |
|---|---|---|
| Apple Log | Rec.2020 | R(0.708, 0.292) G(0.170, 0.797) B(0.131, 0.046) |
| Apple Log 2 | Apple Wide Gamut | R(0.725, 0.301) G(0.221, 0.814) B(0.068, −0.076) |

所以两者共用一条曲线、只需要两套色域矩阵。这也解释了为什么错配的转换 LUT 表现为「曝光对、高饱和颜色怪」——蓝、紫、橙红漂移最明显。

内置曲线可以重新生成：`python3 程序/make_builtin_luts.py`（生成前会先自检曲线和中性灰）。

### 其它

- **多画幅一次输出**：原画幅 / 16:9 / 9:16 / 1:1 / 4:5 可多选，素材只解码一遍
- **音频四模式**：保留原音 / 静音 / 合并单声道 / 响度标准化（`loudnorm -16 LUFS`）
- **画面微调**：曝光（EV）/ 对比度 / 饱和度 / 色温，在 LUT 之后生效
- **四种输出**：ProRes 422 HQ / ProRes 422 / HEVC 10bit / H.264 8bit
- **试色板**：抽一帧，多个 LUT 各渲一张排成网格对比，所见即所得
- **断点续跑**：跳过已导出的文件
- **导出报告**：13 列 CSV，带 BOM，Excel 双击可读
- **停止即停**：按下 1 秒内掐断 ffmpeg（看门狗线程），半成品自动删除

## 快速开始

### 系统要求

- macOS（在 macOS 15.8 / M3 上开发测试）
- **ffmpeg**（必须，建议 7.0+）
- **Python 3**（系统自带即可）

检查 ffmpeg：

```bash
ffmpeg -version
```

没有的话：

```bash
brew install ffmpeg
```

### 使用

1. 把**整个文件夹**拷到你的 Mac 上（不要只拷 `.app`，它要靠旁边的 `程序/` 目录干活）
2. 双击 `LUT批量导出器.app`
3. 第 ① 栏选素材文件夹 → 第 ② 栏选 LUT 文件夹 → 第 ③ 栏选导出位置
4. 如果识别出是灰片但没有转换 LUT，点 **「仅色彩还原」**
5. 点「开始批量导出」

首次打开如果 macOS 提示「无法验证开发者」：右键点 `.app` → 打开，或到「系统设置 → 隐私与安全性」里放行。

### 自检

换了电脑、升级了 ffmpeg、或者怀疑工具不工作时：

```bash
python3 程序/自检脚本/自检.py
```

61 项检查，覆盖环境、Log 识别、每种输出格式、音轨四模式、多画幅、画面微调、LUT 强度、试色板、导出报告、内置曲线。全绿就说明链路没问题。

## 技术说明

### 性能（MacBook Air M3，8 核）

| 素材 | 输出 | 速度 |
|---|---|---|
| 4K 30p | HEVC 10bit 40M | 0.51× 实时 |
| 4K 30p | ProRes 422 | 0.29× 实时 |
| 1080p 30p | HEVC 10bit | 1.77× 实时 |

### 为什么不做多进程

三维 LUT 是纯 CPU 逐像素标量运算，实测多开 ffmpeg 进程只提升到 1.11×，`-filter_threads` 反而更慢。单进程已经吃满 CPU，所以保持串行。

ffmpeg 没有 GPU 的 3D LUT 滤镜，这块快不了。

### 已知限制

- 只支持 `.cube` 三维 LUT，不支持 Adobe `.look` / `.xmp`
- 不做水印 / 字幕烧录（依赖 ffmpeg 的 `drawtext`，很多发行版没编译）
- 内置还原曲线对高光按 Rec.709 上限直接截断，不做柔和滚降。极亮天空的过渡会比正规转换 LUT 稍硬一点，可用画面微调压 0.2–0.3 EV 补
- Apple Log 1 / 2 无法从画面数据区分，需要按机型手动指定

### 踩过的坑（留个记录）

- `lut3d` 的路径参数名在 ffmpeg 各版本不同（`file` vs `filename`），改为启动时自动探测
- 裸写 `lut3d=file=X[out]` 会把 `[out]` 吞进文件名，必须在文件名后有其它参数
- 一旦指定 `-map "[outv]"`，`-map 0:a?` 必须显式写，否则音轨全丢
- 彩色标签要显式写 `setparams=color_primaries=bt709:color_trc=bt709:colorspace=bt709`，否则播放器靠猜导致偏色发暗
- `colortemperature` 滤镜是 **K 值越低画面越暖**，界面的「暖」要映射成 `6500 - temp*25`
- `signalstats` 判 Log 前必须 `format=yuv420p` 归一化，否则 10bit 素材 YAVG 500+ 设不了阈值
- WKWebView 默认不实现 `WKUIDelegate`，`confirm()` 会**静默返回 false**——页面里所有确认框都变成「点了没反应」
