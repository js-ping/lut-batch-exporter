# LUT 批量导出器 · 使用说明

把 iPhone 用 **Blackmagic Camera** 拍的 **Apple Log 2 灰片**，批量套上你自己的 LUT，一口气导出成正常颜色的成片。

不需要打开 Resolve，不需要剪映，不需要一条条手动加滤镜。

---

## 怎么打开（两种方式，选一个）

| 方式 | 怎么用 | 适合 |
|---|---|---|
| **① 原生 app（推荐）** | 双击文件夹里的 **`LUT批量导出器.app`** | 独立 Mac 窗口，不开浏览器、没有标签页、不会因为浏览器卡住而丢进度 |
| ② 终端 + 浏览器 | 双击 `启动.command` | 备用方案。app 万一打不开，用这个必定能跑 |

原生 app 的样子和浏览器里一模一样，但它是自己的窗口：

- 关窗口 / ⌘Q 退出时，后台服务和 ffmpeg 一起结束，不留残余进程
- 强制退出 app 也不会留下后台进程（3 秒内自动清理）
- 快捷键：`⌘R` 重载界面、`⌘[` 返回主界面、`⌘0` 实际大小、`⌘Q` 退出
- **页面关掉不影响正在跑的批处理**——任务在后台服务里跑，重新打开界面还能看到实时进度

> 想换电脑用：把**整个工具文件夹**拷过去（不要只拷 `.app`，它要靠旁边的 `程序/` 目录干活）。

---

## 这个工具是什么

一句话：**拖一个文件夹进来，选一个 LUT，点开始，去干别的。**

它背后是 ffmpeg 在跑，但你把命令行的东西全都不用碰。

### 模块总览

| 区块 | 干什么 |
|---|---|
| **① 素材文件夹** | 指定灰片在哪，自动找出所有视频（含子文件夹），**逐条体检**并自动判断素材是不是 Log 灰片 |
| **② LUT 库** | 指定 `.cube` 文件在哪，列出全部 LUT；可搜、可收藏、可看最近用过；填进「① 转换」和「② 风格」两个槽 |
| **③ 输出设置** | 输出格式、**一次出多个画幅**、音频处理、画面微调、导出到哪里 |
| **④ 运行** | 进度条、实时日志、失败原因、剩余时间、**导出报告** |
| **✦ 试色板** | 先只抽一帧，把一堆 LUT 各套一遍排成网格看效果，挑好了再批量跑 |

## 30 秒快速上手

1. 双击 **`LUT批量导出器.app`**（第一次打开如果提示「无法验证开发者」，右键点它 → 选「打开」→ 再点「打开」）
2. 第 ① 栏点「选择」→ 选中你放着灰片的文件夹
3. **看第 ① 栏那个「Log 识别」框**：工具会告诉你这批素材是不是灰片、依据是什么
4. 点框里的 **「按识别结果自动挑转换 LUT」**，它会从你的 LUT 库里挑一个匹配的填进 ① 槽
   - 如果库里没有转换 LUT，框下面会亮一条橙色警告，告诉你需要先准备一个
5. 想再叠一个风格 LUT，就找到它，点右边 **②**
6. 第 ③ 栏选 **HEVC 10bit（发平台）**，再选一个导出文件夹
7. 点右下角 **开始批量导出**

导出完，点日志下方的「📂 打开导出文件夹」直接看片；点「📄 导出报告」看这一批的详细清单。

> **第一次用，强烈建议先在第 ✦ 栏点一下「生成试色板」**。它抽一帧，把 LUT 各套一遍摆成网格，几秒钟就知道哪个好看、哪个不对，不用整批跑完才发现颜色是错的。

## 每一步的详细用法

### ① 素材文件夹

| 按钮 | 行为 |
|---|---|
| **选择** | 弹出 macOS 原生选文件夹对话框 |
| 输入框 | 也可以直接把 Finder 里复制的路径粘进去，回车生效 |
| **读取素材** | 重新扫描一遍（改过文件之后用） |
| **在访达中打开** | 打开当前填的文件夹看看 |

扫描时会做两件事：

**一、规格标签**——多少条、总体积、编码、分辨率、帧率、位深、时长、色彩标签、音轨。

**二、逐条体检清单**——每条素材一行：文件名、分辨率、时长、判定徽章。

| 徽章 | 含义 |
|---|---|
| 橙色 **Log 灰片** | 这条素材是 Log 曲线，需要转换 LUT |
| 绿色 **已转换** | 这条素材已经是 Rec.709，不需要转换 LUT |
| 红色 **8bit** | 源素材只有 8bit，套 Log 转换 LUT 可能出现色阶断层 |
| 灰色 **待确认 / 未判定** | 判断不出来，建议用试色板看一眼 |

### Log 识别框（第 ① 栏里的那个方框）

工具会用两种办法判断素材是什么曲线：

| 依据 | 可靠性 | 显示 |
|---|---|---|
| **文件元数据**（ProRes / HEVC 里 Apple 写的色彩标签） | 最可靠 | `元数据确认` / `元数据推断` |
| **画面特征**（抽一帧算饱和度和黑位，Log 画面必然低饱和、黑位抬高） | 只能判断「像不像 Log」 | `画面特征推断` |

**它诚实地承认自己分不清 Apple Log 和 Apple Log 2**——两者的像素特征几乎一样，只有机型不同（iPhone 15/16 Pro 是 Apple Log，17 Pro 起是 Apple Log 2）。

所以方框里有个下拉菜单，可以手动指定：

| 选项 | 什么时候用 |
|---|---|
| **自动判断** | 默认。按元数据优先、画面特征兜底 |
| **我拍的是 Apple Log 2（iPhone 17 Pro 起）** | 自动判断结果不对，或者你确知机型 |
| **我拍的是 Apple Log（iPhone 15/16 Pro）** | 同上 |
| **已经转换过（直接叠风格 LUT）** | 素材不是灰片，不需要转换 LUT |

改了下拉菜单后，① 槽会自动清空并重新匹配一次，避免新旧曲线混用。

**最重要的那道拦截**：如果素材是 Log 灰片、但 ① 槽是空的，第 ② 栏底部会亮一条橙色警告，直接告诉你「风格 LUT 直接套在灰片上会发灰、发脏、肤色发橙」。这不是吓唬人，是这套工具最容易出废片的地方。

#### 两个按钮的区别

方框里有并排两个按钮，解决的是同一个问题（把灰片还原成正常画面），但走的路不同：

| 按钮 | 用什么 | 什么时候用 |
|---|---|---|
| **从我的库里挑转换 LUT** | 你自己 LUT 文件夹里的 `.cube` | 你手上有正规的转换 LUT（Apple 官方、LUT 卖家附带的 conversion 包） |
| **仅色彩还原** | **工具自带的曲线，不需要任何文件** | 你手上全是风格 LUT，没有转换 LUT |

#### 「仅色彩还原」是什么

点一下，工具会把内置的转换曲线挂到 ① 槽，只做**色彩还原**这一件事：

- 灰片 → 颜色和对比正常的普通画面
- **不叠加任何风格**（② 槽会被清空，所以叫「仅」）
- 不需要你去下载、购买、寻找任何 `.cube` 文件

内置曲线不是随便凑的「基础校正」，是按 Apple 白皮书公开的曲线常量 + 色域原色**现场用数学算出来的**，有据可查：

| 项目 | 值 | 来源 |
|---|---|---|
| 曲线常量 | `R0=-0.05641088`、`Rt=0.01`、`c=47.28711236`、`β=0.00964052`、`γ=0.08550479`、`δ=0.69336945` | Apple Log / Apple Log 2 白皮书 |
| 校验点 ① | 18% 灰编码后 = **0.48827** | 白皮书「18% 灰落在 10bit 500」 |
| 校验点 ② | 满格码值解出 **12.0 倍**反射率 | 白皮书「clip at 1200% scene reflection」 |
| 色域（Log 2） | Apple Wide Gamut：R(0.725,0.301) G(0.221,0.814) B(0.068,−0.076)，D65 | Apple Log 2 白皮书 |
| 色域（Log 1） | Rec.2020：R(0.708,0.292) G(0.170,0.797) B(0.131,0.046)，D65 | ITU-R BT.2020-2 |

> **一个反直觉的事实**：Apple Log 和 Apple Log 2 的 **gamma 曲线完全相同**，只是色域从 Rec.2020 换成了 Apple Wide Gamut。所以两者的差别不在明暗，而在**高饱和颜色**（蓝、紫、橙红）。这也是为什么错配的转换 LUT 看起来「曝光对了但颜色有点怪」。

工具会按识别到的机型自动选对应那一版；你在下拉里改成 Apple Log，内置曲线会跟着换。

**用它的结果**：画面变成「颜色正确但不带风格」的状态。想加风格就在 ② 槽再选一个你的风格 LUT，那时顺序就对了（先还原、后风格）。

#### 内置曲线放在哪

`程序/luts/` 下两个 `.cube` 文件，各约 950 KB。

想重新生成、或者想自己改参数：双击终端跑 `python3 开发/make_builtin_luts.py`（会先自检曲线再生成）。

### ② LUT 库

| 元素 | 行为 |
|---|---|
| **选择** | 选 LUT 所在文件夹，会连子文件夹一起扫 |
| 搜索框 | 边打边过滤，文件名和所在文件夹名都参与匹配 |
| **☆ / ★** | **收藏**。点一下收藏，再点一下取消。收藏记在本地 |
| **★ 只看收藏** | 只显示收藏过的 LUT。库里几百个的时候，把常用的十几个收藏起来，以后一开就是这个短列表 |
| **最近用过** | 显示最近 12 个用过（真正跑过批处理）的 LUT |
| 每行左边的勾选框 | 标记「待试色」，试色板只渲染勾上的 |
| 每行的 **①** | 填进「转换 LUT」槽 —— Apple Log 2 → Rec.709 的技术转换 |
| 每行的 **②** | 填进「风格 LUT」槽 —— 叠在上面的创作风格 |
| **全选筛选结果 / 反选 / 清空勾选** | 批量勾选试色用。也可以按住鼠标拖过一串方框刷选，或 Shift + 点击选一整段 |
| 每行最右的 **✕** | **从列表移除**。只影响列表显示，磁盘上的 `.cube` 文件一个都不动 |
| **已隐藏 N · 恢复** | 出现在列表标题旁，点一下把所有收起来的 LUT 放回来 |

#### 「Log 用 / 709 用 / 判不准」这枚徽章是什么意思

这是这个工具最容易被忽略、但最容易出废片的地方：

- **Log 用** —— 这个 LUT 设计给**未还原的 Log 灰片**。套上去会把扁平的灰片拉开反差，一般就是转换 / CST 型
- **709 用** —— 设计给**已经还原成 Rec.709 的正常画面**。直接套在灰片上会发灰、发脏、肤色发橙
- **判不准** —— 曲线特征不明显，文件名也没有线索。悬停能看实测数字，建议先用试色板看一眼

**为什么不只看文件名**：同一个「万能 LUT 包」，有的文件叫 `AppleLog2_to_Rec709`，有的就叫 `01-风光人像`，还有的把文件名改成中文。真正能分开它们的是曲线形状：

| | Log→709 转换 | 风格 LUT |
|---|---|---|
| 中性轴中段斜率 | 约 2.2（大幅拉开反差） | 0.86 ~ 1.2（只微调） |
| 黑位 | 0.000 | 常抬到 0.02~0.09（胶片味） |
| 色度倍率 | 1.3 ~ 3.3（把灰片拉开） | 0.6 ~ 1.0（反而收一点） |

所以工具会真的把 `.cube` 读进来，取中性轴（`r=g=b` 那些点）算斜率，再和文件名交叉验证。101 个 LUT 全量分析 0.7 秒，结果缓存起来，第二次打开不重算。

鼠标悬停在徽章上能看到判定理由，例如「文件名含 applelog→709；中性轴斜率 2.20，黑位 0.000」。

> **文件夹名和判定不一致时信判定**。`柯达2383` 这种名字看着像风格 LUT，实际是「相机 Log → 2383」的转换包，曲线斜率 2.0、色度 2.0，工具会正确判成 `Log 用`。

#### 关于「从列表移除」

一个 LUT 包动辄几十上百个，常用的其实就几个。把不用的收起来，列表就清爽了。

- **不会删你的文件**。这里做的是「收起来」不是「删除」，`.cube` 原封不动躺在原来的文件夹里
- 如果被收起来的那个正挂在 ① 或 ② 槽里，**会顺手把槽清空**，避免出现「看不见它却还在生效」
- 想彻底删掉文件，用「在访达中打开」（素材文件夹那栏有这个按钮）自己删——工具不碰你的原始文件
- 记录存在 `程序/lut_hidden.json`，删了只丢这份清单，LUT 全部重新出现

每行右侧还会显示它来自哪个子文件夹，LUT 包有分目录时一眼能看出来。


### ③ 输出设置

#### 输出格式

| 格式 | 用什么场景 | 体积感受 |
|---|---|---|
| **ProRes 422 HQ（归档母版）** | 留底、以后还要再剪辑、要最高画质 | 极大。4K 素材 1 分钟约 1.8 GB |
| **ProRes 422（轻量归档）** | 留底但想省点空间 | 大。约为 HQ 的 70% |
| **HEVC 10bit（发平台）** | 发小红书/抖音/微信、直接看、给剪辑用 | 小。4K 素材 1 分钟约 300 MB |
| **H.264 8bit（最兼容）** | 老设备、老播放器、某些平台上传报错时兜底 | 小，但会掉到 8bit |

**「质量」三档只对 HEVC 和 H.264 有效**（高 60 / 标准 40 / 小 20 Mbps），选 ProRes 时这一项不起作用——ProRes 是固定码率格式。

#### 画幅（可多选）

选几个画幅就出几个版本，文件名自动加画幅后缀。**每个画幅是一次独立的解码 + 编码**，所以选 4 个大约要跑 4 倍时间（裁小的画幅便宜一点），预估时长里已经算进去。

| 画幅 | 后缀 | 用途 |
|---|---|---|
| **原画幅** | 无 | 保持素材原比例 |
| **16:9 横屏** | `_16x9` | B站 / YouTube |
| **9:16 竖屏** | `_9x16` | Reels / 抖音 / 视频号 |
| **1:1 方形** | `_1x1` | 朋友圈 / 头像位 |
| **4:5 竖幅** | `_4x5` | 小红书 / Instagram |

规则：

- **中心裁切**——从画面正中裁，不缩放、不拉伸、不加黑边。4K 3840×2160 裁 9:16 得到 1216×2160
- 素材比例和目标比例一致时**自动跳过裁切**，不浪费画质
- 宽高强制取偶数，避免编码器报错
- 一次选 4 个画幅 = 每条素材出 4 个文件，底部状态栏会实时显示「N 条 × M 画幅 = 共几个文件」

> ⚠️ 中心裁切对构图有要求：主体偏左偏右时，竖屏版可能把人裁掉一半。这种素材建议单独跑一遍，或者先拍的时候就把人放中间。

#### 导出位置与文件名

**文件名后缀**默认 `_LUT`。原片 `BM_0001.mov` → 导出 `BM_0001_LUT.mp4`（选了竖屏则是 `BM_0001_LUT_9x16.mp4`）。子文件夹结构会一并保留。

**跳过已存在**默认勾选。中断了直接再点一次开始，已经导出的会跳过，只补没做的。想全部重做就取消勾选。

### 高级参数

#### 音频处理

| 模式 | 行为 | 适用 |
|---|---|---|
| **保持原样** | 能直拷就直拷，`.mp4` 装不下 PCM 时自动转 AAC | 默认，画质音质无损 |
| **静音** | 去掉音轨 | 要后期统一配音 / 配乐 |
| **转单声道** | 转成单声道 AAC 128k | 口播、采访，后期统一声道 |
| **响度标准化** | 响度拉到 -16 LUFS（短视频平台标准） | 一批素材音量忽大忽小，先统一 |

> **保持原样**是最安全的选择。只有当你确定后期要重新处理声音时，才用「静音」——去掉音轨能让文件小一点、处理快一点。

#### LUT 强度

0% – 100%，默认 100%。**只对最后一个 LUT 生效**。100% = 完全套用；50% = 一半效果（和原图混合）。用来把太浓的风格 LUT 调淡。转换 LUT 始终保持 100%。

#### 输入色域矩阵

自动 / BT.2020 / BT.709，默认自动。一般不用改。只有导出后颜色明显偏（比如整体偏绿偏紫）时，才试着手动指定。

#### 画面微调（在 LUT 之后生效，统一整批素材）

| 参数 | 范围 | 说明 |
|---|---|---|
| **曝光** | -1.5 ~ +1.5 EV | 按真实曝光的倍数调整，不是简单拉亮。整批偏暗就往正调 |
| **对比度** | 0.70 ~ 1.40 | 1.00 是原样。往高走画面更"实"，往低走更平 |
| **饱和度** | 0.40 ~ 1.80 | 1.00 是原样。LUT 洗完还是觉得寡淡，加一点 |
| **色温** | -100（冷）~ +100（暖） | 往左偏蓝、往右偏黄。用来统一一批素材的色温，或者修白平衡偏差 |

这四项作用在 **LUT 处理之后**，也就是在已经变回正常颜色的画面上做微调——和你在剪辑软件里调色轮是同一个位置。

改了任何一项，折叠标题会变成「高级参数（含画面微调改动）」，提醒你这批不是默认值。

> 微调是**整批统一**的，不会逐条自适应。如果这批素材曝光差别很大，先分开跑，别指望一个值救全场。

### ④ 运行

| 元素 | 说明 |
|---|---|
| 大号百分比 | 整体进度（按输出任务数算，选了多画幅时任务数 = 条数 × 画幅数） |
| 细进度条 | 当前这一条的进度 |
| **时长那一行** | 已处理多长 / 素材总长 · 剩余约多久 · 整批约多久 · 当前速度 |
| 日志区 | 每条的开始、完成、失败原因、体积、耗时，全部按时间记录 |
| **停止** | **按下就停**，1 秒内掐断当前 ffmpeg，不会让你等这条跑完 |
| **📄 导出报告** | 跑完出现，点开在访达里定位到这次生成的 CSV 报告 |
| **📂 打开导出文件夹** | 直接打开输出目录 |

失败的条目会单独标红并写明原因，其它条目继续跑，不会因为一条出错整批停下。跑完后状态栏还会汇总失败条数，鼠标悬停能看具体原因。

#### 要跑多久 / 还剩多久

**开始之前**底部状态栏和运行面板就会给结论：

```
素材总长 18:40    整批预计需要 约 8 分钟（估）    待处理 40 / 跳过 3 个文件
```

这个数字是在你这台机器上实测标定出来的，不是拍脑袋的常数：

| 输出尺寸 | HEVC | H.264 | ProRes 422 |
|---|---|---|---|
| 3840×2160 | 0.89x | 0.93x | 0.31x |
| 1920×1080 | 3.16x | 3.47x | — |

（0.89x = 一秒钟能处理 0.89 秒素材，也就是比实时略慢）

工具按**输出像素数**反推，所以裁成竖屏之后像素变少、速度变快也能算进去；LUT 级数、强度混合、质量档位都会往下打折。

**跑起来之后**以实测为准，每 0.4 秒刷新：

```
已处理 05:20 / 18:40    剩余 约 02:10    整批 约 07:30    速度 3.34x
```

- 剩余时长 = 还没处理的素材长度 ÷ 当前实测速度
- 每条跑完用实际时长校准，误差不累积
- 跳过 / 失败的文件也算进「已处理」，否则跑完了剩余时长还挂在非零
- 结束后显示「整批实际用时」

> 预估和实际通常差在 10% 以内。差得多说明这批素材的编码比标定时更重（比如 4:2:2 10bit 的 HEVC 源，解码比 ProRes 更吃 CPU），但它会在头几秒内自我校正，看「剩余」那个数就行。

#### 点「开始批量导出」之后，什么情况下会先弹一个框

三种情况会先问一句（不是拦你，是提醒）：

| 情况 | 提示 | 为什么 |
|---|---|---|
| 导出目录 == 素材目录 | 导出目录和素材目录是同一个 | 输出会和原片混在一起，下次扫描还会把输出当成素材扫进来 |
| 一个 LUT 都没选 | 一个 LUT 都没选 | 这样只做色彩标签修正，画面没有任何调色变化 |
| 输出文件 > 40 个 | 要生成 N 个文件（附预计时长） | 防止手滑一次跑出几百个文件 |

弹窗里 **ESC / 点遮罩 = 取消**，**回车 = 确认**。

> 这几个框是自己画的，不用系统自带弹窗。早先版本用的是浏览器 `confirm()`，而原生窗口（WKWebView）默认不实现它、会**静默返回「取消」**——表现就是点「开始导出」毫无反应。v1.4 改成自绘，app 和浏览器里行为完全一致。

#### 关于「停止」

按下去之后：

1. 按钮立刻变成 **「正在停止…」** 并锁住（防止连点）
2. 后台在 **1 秒内**给 ffmpeg 发终止信号，不退就强杀
3. **当前这条的半成品文件会被删掉**——这一步很重要，不删的话下次开「跳过已导出」会把它当成已完成而跳过，你就得到一个坏文件
4. 已经跑完的文件**原样保留**，不受影响
5. 界面状态复位，可以立刻改设置重新开始

> 早先的版本是「等当前这条跑完再停」。一条 4K 素材套两条 LUT 大约 0.5 倍实时，也就是说一条 1 分钟的片子要等 2 分钟才能真正停下——这就是「按了很难停」的原因。现在不会了。

## 参数和规则，逐条解释

### 最重要的规则：Apple Log 2 是两步调色

Apple Log 2 的原始画面是灰的、低对比、低饱和。要变成正常颜色，需要：

| 步骤 | 名字 | 作用 | 典型文件名 |
|---|---|---|---|
| 第一道 | **转换 LUT** | 把 Log 曲线翻译成 Rec.709，画面恢复正常的对比和颜色 | `AppleLog2_to_Rec709.cube` |
| 第二道 | **风格 LUT** | 在这个正常画面上加电影感 / 胶片感 / 冷暖调 | `Kodak_2383.cube`、`Teal_Orange.cube` |

**三种常见情况的处理方式：**

1. **LUT 包写明 "Apple Log 2 version / conversion built in"** → 它是「转换+风格」二合一，只需要填槽 ①（或只填 ②，效果一样，只有一个 LUT 时不会重复处理）
2. **只有纯风格 LUT（给 Rec.709 素材用的）** → 必须槽 ① 放转换 LUT、槽 ② 放风格 LUT
3. **只有转换 LUT** → 只填槽 ①，导出的是「颜色正确的普通画面」，然后你可以再剪辑时自己调

**如果搞错会怎样？** 把纯风格 LUT 直接套在灰片上 → 画面发灰、发脏、肤色发橙发绿。看到这个症状就是 LUT 类型不对，不是工具坏了。工具在你没挂转换 LUT 时会主动亮橙条拦你一下。

> **常见的坑**：网上买的「万能 LUT 包」（那种按场景命名的：风光人像 / 海边人像 / 城市街景）**几乎全是风格 LUT**，是给已经调好色的 Rec.709 画面用的。它们不能直接套在 Apple Log 2 灰片上。你需要单独准备一个 Apple Log 2 → Rec.709 的转换 LUT。

### 导出文件到底经历了什么

按顺序：

1. 读原片，按原片的色彩矩阵把 YUV 解成 10bit RGB
2. 套第一道 LUT（33×33×33 三维查找表，四面体插值）
3. 套第二道 LUT（如果填了；强度不是 100% 时用混合比例）
4. 需要多画幅时，在这里按目标比例中心裁切，宽高取偶数
5. 画面微调：曝光 → 对比度/饱和度 → 色温
6. 转回 YUV，按你选的格式和码率编码
7. **强制把色彩标签写成 `bt709 / bt709 / bt709`**

第 7 步很关键。不写这一层，导出的文件在别人机器上、在微信里、在网页播放器里会莫名偏色发暗——很多「导出后颜色不对」的锅都在这里。

### 音轨

能原样拷贝就原样拷贝，不重新压缩。唯一例外：ProRes 素材的音频是 PCM 无压缩格式，导成 `.mp4` 容器塞不进去，会自动转成 AAC 256k。导成 `.mov` 则始终原样保留。选了「单声道 / 静音 / 响度标准化」就按你的选择来。

## 性能参考

本机实测（MacBook Air M3，macOS 15.8，**1 级 LUT**，40 Mbps，ProRes 源，输出原画幅）：

| 输出尺寸 | HEVC 10bit | H.264 8bit | ProRes 422 |
|---|---|---|---|
| 3840×2160 | **0.89× 实时**（10 分钟素材 ≈ 11 分钟） | 0.93×（≈ 11 分钟） | 0.31×（≈ 32 分钟） |
| 1920×1080 | **3.16× 实时**（10 分钟素材 ≈ 3 分钟） | 3.47×（≈ 3 分钟） | — |

**为什么 4K 这么慢？** 三维 LUT 的逐像素查找是纯 CPU 计算，4K 一帧 830 万像素，每一帧都要过一遍查找表。ffmpeg 这个环节没有 GPU 加速。这是真实速度，不是工具的问题——Resolve 里批量渲染同样的活儿，时间也是同一个量级。

**多一级 LUT 会再慢一点**：每多一级 `lut3d` 大约多一成 CPU 开销（强度不满 100% 时还要多算一遍混合，约慢三成）。预估时长里已经按这个折算过。

**多画幅是几乎成倍的**：每个画幅是一次独立的解码 + 编码，实测 4 个画幅的耗时是 1 个画幅的 **3.75 倍**（裁小的画幅像素少、便宜一点，所以不到 4 倍）。选了 4 个画幅，预估时长也会按 4 份算。

> 早先版本说「素材只解码一遍、多画幅只慢 1.4~1.8 倍」，这是错的，已更正——那种做法要在一个 ffmpeg 里挂多个输出，当前实现是每个画幅单独跑一遍。

**实操建议**：晚上丢进去跑，或者先去干别的。批量 30 条 4K 短片（每条 20 秒）大约 40 分钟。

**想让速度快一点**：如果只是发小红书/抖音，可以在 Blackmagic Camera 里拍 1080p 或 4K 但降低帧率，处理时间直接减一大截。

## 常见问题 FAQ

**Q：导出后画面还是灰的，没变化？**
A：两种可能。① 槽里没填 LUT，工具只做了色彩标签修正（日志里会写「未选 LUT，仅做标签修正」）。② 填的 LUT 本身就是低对比的"基础校正"型。换一个转换 LUT 试试。

**Q：导出后颜色偏了，发绿 / 发紫 / 肤色发橙？**
A：几乎都是 LUT 类型不匹配。用纯风格 LUT（给 Rec.709 用的）直接套在 Log 灰片上就会出现这种症状。先填一个 Apple Log 2 → Rec.709 的转换 LUT 到槽 ①。

**Q：工具提示「这个 LUT 库里没找到任何转换 LUT」，怎么办？**
A：说明你那包 LUT 全是风格型的（网上按场景命名的包基本都是）。你需要单独找一个 **Apple Log 2 → Rec.709** 的转换 LUT。来源：Apple 官方 Log 白皮书配套 LUT、LUT 卖家附带的 conversion 包、或者在 DaVinci Resolve 里用 Color Space Transform 生成一个 `.cube`。没有转换 LUT 时，工具仍然能跑，但出来的片子不会正常。

**Q：Log 识别框说「疑似 Log」，但它其实分不清 Apple Log 还是 Apple Log 2？**
A：对，它诚实地这么写。两者的像素特征几乎一样，靠画面数据分不出来。如果你知道机型，直接从下拉菜单选「Apple Log 2」或「Apple Log」，它会用你选的去匹配转换 LUT。

**Q：竖屏版本把人裁掉一半。**
A：中心裁切是按画面正中算的。主体偏左偏右时必然出这个问题。解决办法：① 拍摄时把人放中间；② 单独跑一遍竖屏，换一张构图合适的素材；③ 竖屏版在剪辑软件里另外做。

**Q：一次出 4 个画幅，文件太多了。**
A：只勾你需要的那一两个。默认只出「原画幅」。发小红书就勾 4:5 和 9:16，发 B 站就勾 16:9。

**Q：LUT 效果太浓了。**
A：把「高级参数 → LUT 强度」拉到 60%–70%。注意强度只对最后一个 LUT 起作用，转换 LUT 始终保持 100%。

**Q：想让整批素材亮一点 / 暖一点。**
A：用「高级参数 → 画面微调」里的曝光和色温。它们是整批统一的，先用试色板看一帧确认效果，再批量跑。

**Q：提示「未找到 ffmpeg」。**
A：打开「终端」，粘贴这一行回车，装完再双击启动：

```
brew install ffmpeg
```

没装 Homebrew 的话先装 Homebrew（brew.sh 上有官方一行命令）。装完可以重新双击 `启动.command`。

**Q：我的 LUT 是 `.look` / `.xmp` 格式，不是 `.cube`。**
A：ffmpeg 只认 `.cube`、`.3dl`、`.dat`、`.m3d`、`.csp` 这几种三维 LUT。`.look` 是 Adobe 的封装格式，`.xmp` 是 Lightroom 的预设，都不是标准三维查找表。解决办法：在 Photoshop / Resolve 里把那个 LUT 转存成 `.cube`（Resolve 里右键 → Generate LUT），或者找 LUT 卖家要 `.cube` 版本。

**Q：能处理 ProRes 素材吗？**
A：能，而且解码更快。但输出体积注意留空间——4K ProRes 一小时约 100 GB 级别。

**Q：导出的文件在 QuickTime 里正常，在微信里偏色。**
A：先确认用的是 HEVC 版本（H.264 在国内部分安卓机型上色彩管理有 bug）。如果还偏，把输出格式换成 H.264 8bit 再试，或者用「输入色域矩阵」手动指定 BT.709。

**Q：中途关掉了，能接着跑吗？**
A：能。重新双击启动，界面会记住上次的全部设置（包括画幅、音频、微调），「跳过已存在」保持勾选，点开始就会跳过已完成的部分。

**Q：一次能跑多少条？**
A：没有硬上限，几百条也没问题，只是要等。文件夹结构和文件名完全保留，导完还是一条条对得上。

**Q：会改原片吗？**
A：绝对不会。**原片只读**，所有输出都是新文件，写到你在第 ③ 栏指定的目录里。就算把导出目录设成素材目录，加后缀后也是新文件，不会覆盖。

**Q：怎么退出工具？**
A：用 app 的话直接 `⌘Q` 或关窗口，后台服务会一起结束。用 `启动.command` 的话，关掉那个显示启动信息的**终端窗口**即可。

**Q：正在批量跑，我不小心把窗口关了，会中断吗？**
A：**不会**。任务跑在后台服务里，跟界面无关。重新打开界面（或按 `⌘R`）就能看到当前进度和日志。

**Q：页面对我来说容易卡，能用别的吗？**
A：直接双击 `LUT批量导出器.app`，那是原生窗口，不经过 Chrome/Safari，不会有标签页被系统挂起的问题。另外 v1.1 起日志改成增量渲染，长时间跑也不会拖慢界面。

**Q：点「选择」没弹出文件夹窗口？**
A：v1.0 的这个 bug 已经修掉了。万一还有异常，直接把 Finder 里复制的路径**粘贴**到输入框里，回车一样生效。

**Q：端口被占用怎么办？**
A：工具会自动往上找空闲端口（8787、8788……），终端窗口里显示的地址就是当次实际地址。也可以用环境变量指定：`LUT_PORT=8800`。

**Q：按了停止，为什么还跑了好一会儿才停？**
A：这是 v1.2 及更早版本的行为——它要等当前这条素材**整条跑完**才停。一条 4K 素材套两条 LUT 约 0.5 倍实时，1 分钟的片子就要等 2 分钟。**v1.3 起改成按下即停**：1 秒内掐断 ffmpeg，半成品自动删除，已经跑完的文件保留。

**Q：我没有转换 LUT，只有一堆风格 LUT，能用吗？**
A：能。点 Log 识别框里的 **「仅色彩还原」**，工具用自带的内置曲线把灰片还原成正常画面，不需要任何 `.cube` 文件。想加风格再往 ② 槽里选。曲线是按 Apple 白皮书常量算的，不是近似货。

**Q：内置还原出来的画面，和正规转换 LUT 差多少？**
A：曲线部分完全一致（同一个公式、同一组常量）。差别只可能出现在高光处理上：内置版本按 Rec.709 上限直接截断，正规转换 LUT 有时会在高光做个柔和滚降。所以如果你的画面有很亮的天空、窗户，内置版的高光会稍微「硬」一点。可以配合「画面微调」里的曝光往回压 0.2–0.3 EV。

**Q：为什么我的素材目录里多了一堆 `_LUT` 后缀的文件？**
A：那是**导出结果**，不是原片。如果你把「导出位置」设成了素材目录（或者留空），输出和原片就会混在一起。建议把导出目录单独指定一个文件夹。混在一起也不影响使用，但下次扫描会把它们也当素材扫进来。

## 数据安全与免责

- **全程本地处理**。不联网、不上传、不遥测、不需要账号。工具只监听本机回环地址 `127.0.0.1`，同一个 Wi-Fi 下的其它设备也访问不到。
- **不修改原始素材**。只读打开，只写新文件。
- **唯一的网络行为**是启动时在浏览器打开本地地址，仅此。
- 工具会记住上次用的文件夹和设置，存在 `程序/config.json`；收藏的 LUT 存在 `程序/lut_fav.json`；LUT 用途的判定结果缓存在 `程序/lut_meta.json`。都是纯本地文本，随时可以删（删了就是恢复默认 / 重新分析一遍）。
- 运行日志、试色板临时图、素材信息缓存都存在 `运行记录/` 目录里，可以随时清空，不影响功能。
- 这不是商业产品，没有付费、没有激活、没有后门。代码全部是纯文本，`程序/server.py`、`程序/lut_analyze.py` 和 `程序/static/index.html`，你随时可以让任何一个懂 Python 的人逐行检查。
- 唯一的外部依赖是 ffmpeg（开源，GPL/LGPL）和 macOS 自带的 Python 3。

| `启动.command` | 备用入口，双击用浏览器打开 |
| `使用说明.html` | 就是你正在看的这份说明的网页版 |

其余都是程序内部文件，正常使用不需要打开：

| 路径 | 是干什么的 |
|---|---|
| `程序/` | 运行必需（后端、界面、内置还原曲线） |
| `开发/` | 源码和维护工具，只有改代码或排查问题才用 |
| `运行记录/` | 日志、试色板临时图、缓存，随时可清空 |

> `.app` 不能单独拖到「应用程序」文件夹——它要靠旁边的 `程序/` 干活。要移动就整个文件夹一起移，或者给 `.app` 做个替身。
